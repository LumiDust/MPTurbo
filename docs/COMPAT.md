# 独立联机：兼容性与等待处理

目标仅为 RimWorld 1.7。Multiplayer、RimWorld Together 是参考资料，不是运行依赖。

## 这一阶段已经落地的规则

| 问题 | 当前实现 | 验证 |
|---|---|---|
| 仅把数值广播，开关/上限却各端不同 | `SpeedPolicy` 把 Enabled、Multiplier、MaxRate、Revision 一起交给服务器；按同一修订广播 | 双客户端测试比较完整 policy |
| 多人同时改设置产生乱序 | 服务端串行化写入及原子落盘；广播修订单调递增；客户端忽略过期修订 | 并发写入测试 |
| 非控制者绕过 UI 改设置 | `--controller-only` 权限由服务端分配并校验；不相信客户端自报角色 | 非控制者请求失败，房间状态不变 |
| 不兼容 modpack 仍进房间 | 完整游戏 build、协议/客户端版本、模组/配置指纹精确比对 | 错版本、错指纹、旧游戏版本均握手失败 |
| 同一客户端重连时旧编辑误发到新服务器 | 每次操作固定发起时的会话；排队和下载都随旧会话取消 | 两台真实服务器＋确定性队列屏障回归 |
| 网络回调碰游戏对象 | 所有 socket 事件排入游戏线程队列，并带会话代数防止旧连接污染 | 游戏适配层代码审查；游戏内仍待验证 |
| 断线时回退本地仿真设置 | 持续等待，显式重连或退出房间；不悄悄启用本地倍率 | `SpeedAuthority` 状态测试 |
| 相同快照每次都重新下载 | 完成文件先校验长度＋整个 SHA256，命中后直接结束 | 删除服务器 blob 后，再次使用完整缓存仍成功 |
| 下载取消后必须从头开始 | `.part`＋manifest sidecar；逐块验证复用；损坏块重下 | 中断/续传、坏块、旧 sidecar 验证 |
| 损坏快照踢掉健康客户端 | 返回当前 requestId 的结构化错误，控制连接保持可用 | 下载出错后仍可修改房间设置 |
| TPS 显示误导 | 真实已完成 tick 的增量/实时时间；不将 `1/MeanTickTime` 当实测 TPS | 暂停、计数重置、追赶不足测试 |
| 旧程序集混装 | 包内只允许三个自有 DLL，引用元数据校验 .NET 10 和零参考模组依赖 | PE/目录/XML/语言键验收 |

共享殖民地：控制者发布存档，其他人下载并载入同一世界；标记类指令经服务端排序后在指定 tick 应用。小人指令、建造蓝图、物品转移和严格锁步尚未实现。

默认额外倍率开启；修改仍须服务端确认。暂停和威胁强制常速保留。单机偏好不会改写房间权威值，联网时也不依据某一台机器的帧率自行降倍率。

## 指纹的范围与局限

客户端在主线程捕获当前激活的 mod 顺序与路径，后台散列实际内容，并导出 JSON 清单。当前检查：

- 所有已启用 mod 的 packageId 和加载顺序。
- `Assemblies/` 下 DLL 内容。
- `Defs/`、`Patches/` 下 XML，以及 `About.xml`、`LoadFolders.xml`。
- 游戏配置目录下其他 mod 的 `Mod_*.xml`。本项目自己的连接地址、名称、HUD 配置排除，因为房间的仿真设置由服务器下发。

图片、声音、语言文本不参与该清单。生成器过滤 Source、bin、obj、隐藏目录，避免开发中间文件被当作游戏内容。

这是保守的一致性门禁，不是任意 mod 的确定性证明：运行时读取其他目录、线程修改状态、外部 DLL、非确定性集合遍历等，仍需要后续扫描与实际命令回放验证。当前尚未生成 Def 数据库最终展开哈希，尚未建立每个第三方 mod 的兼容性数据库。

## 等待分阶段，而不是一个总进度条

当前界面区分：生成指纹、连接服务器、兼容性握手、房间已连接、连接中断、请求快照、分块缓存、完整散列校验完成。所有网络操作有取消/超时和可读错误；出现错误不改当前游戏存档。

已经实现的是**文件传输缓存/续传**，尚未实现**存档对象的增量合并**或**从断点仿真状态追赶至当前服务器 tick**。当前服务器也不运行完整 RimWorld 仿真。

后续进入共享殖民地阶段时，需要：

1. 一致 tick 边界处的存档快照，包含世界、地图、对象 ID、随机状态与命令日志范围。
2. 入场玩家加载并回放时从全局就绪屏障中隔离；追上后再允许输入，其他玩家保持同一确定性时间线。
3. CPU 永久达不到当前速度的玩家，统一降速或明确挂起该玩家；移除掉队闸门不会自动提高仿真能力。
4. 未证明跨地图状态隔离前，不能仅凭切图订阅丢弃其他地图的模拟命令。
5. 不对活着的 Verse 对象做任意后台序列化。游戏线程先取得一致状态，再在后台压缩与散列独立字节。

## 审查中修复的具体缺陷

- 旧版本 `.part` 成功改名后，下次不看最终缓存，导致完整快照重复下载。
- `InvalidDataException` 不继承 `IOException`，错误捕获遗漏会把坏块升级成会话错误。
- 等待调速队列时尚未固定会话，重连后可能把旧请求发到新房间。
- `GameComponent` 基类的无参构造不等于具体类的引擎创建契约；具体类显式提供 `TurboGameComponent(Game game)`。

测试有正例和缓存负对照：临时隔离副本移除完整缓存分支后，回归测试确实失败；当前实现通过。上述测试不等价于游戏内加载验证。

## 运行边界

原型默认监听 loopback。当前没有账号认证/TLS、共享世界 tick/RNG 同步、人物/建筑操作命令、完整存档恢复，也未做 RimWorld 1.7 实机双开验收。联机设置同步是已运行的独立基础能力，完整合作玩法仍按 [ROADMAP.md](ROADMAP.md) 推进。
