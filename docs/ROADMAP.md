# 独立共享殖民地：实现次序与验收

参考模型是 Multiplayer 的共同操作体验与 Together 的独立服务器部署方式。实现由本项目负责；不复用两者的运行时或要求玩家订阅。

## 已完成的可验证切片：0.3.0

- 自有 TCP framing、握手、请求关联、结构化错误与心跳。
- 不引用游戏程序集的专用服务器。
- 服务端持久化的倍率 policy，含启用开关、倍率、速率上限、单调 revision。
- 两客户端双向编辑与权限验证；晚加入、断线、重连、重启的设置一致性。
- 内容寻址快照、256 KiB 校验块、取消/续传、完整缓存零块下载。
- 1.7 mod 连接页与主线程消息队列；保守兼容性指纹。

这些是房间与设置层的独立基础，尚不是游戏状态同步。

## M1：共同存档及稳定对象标识

实现一致 tick 边界处导出/导入世界和地图，明确存档 schema、游戏 build、modpack digest、快照 tick/epoch、RNG 状态。建立跨客户端稳定的 Map/Pawn/Thing ID；运行时引用通过稳定 ID 解析，避免直接传内存地址、哈希码或方法数组下标。

验收：两个 1.7 客户端读取同一测试存档，对静态状态与 ID 表给出相同摘要；拒绝 schema/build/modpack 不匹配；导入失败保留原存档。

## M2：最小共同操作闭环

先支持明确的少量命令：选中/光标（仅表现）、征召/移动、建设标记。命令采用固定类型与参数 schema，服务端分配序号与生效 tick；游戏线程在指定 tick 执行，禁止任意反射方法远程调用。

验收：双端以相同输入日志回放，人物目标与建造标记一致。重复命令去重、过期输入明确处理，拒绝无效实体 ID。

## M3：确定性 tick、随机数和速度档位

权威时间线与倍率变更要在一致的 tick 屏障应用；当前“收到同一 policy”仅证明设置数据一致，尚未解决各端执行时刻一致。同步暂停、常规速度档位以及额外倍率；保存/恢复 RNG；CPU 耗时与网络延迟只用于诊断，不直接决定各客户端仿真行为。

验收：两个独立进程长时间回放相同命令和种子，状态摘要一致；不同 FPS、丢包/延迟、暂停与高倍率场景一致。永久跑不动时选择统一降速或挂起该玩家，而非让一个客户端少模拟。

## M4：掉线重进与等待优化

将现有文件级快照缓存接到真实游戏快照，并加入按 epoch/tick 编号的命令日志。保留已验证的本地状态时从确认水位重放；进程崩溃则从一致快照恢复。接入中新玩家可以在后台追赶，但未追上之前只读、不参与当前就绪屏障。

验收：断线、下载中断、重连同一局、服务器重启、modpack 更新、快照损坏各场景有可重复用例；分别记录网络下载、解压、游戏对象重建、命令回放时间，基于测量优化。不给未经测量的“秒进”承诺。

## M5：第三方 mod 兼容与部署

构建确定性检查与兼容适配登记：UI 变更入口、随机/时间源、集合遍历、异步代码、Harmony 冲突、展开后的 Def 摘要。静态扫描输出候选风险，不将命中 `Rand` 等同于必然不兼容，也不自动同步所有任意 UI 回调。

认证、加密、版本升级、房间迁移、容器发布及实机双开验收在公开稳定版前完成。研究资料保留来源/版本，编译通过与实际游戏验证分开报告。
